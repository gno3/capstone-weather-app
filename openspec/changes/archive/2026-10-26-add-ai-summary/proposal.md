# Proposal

## Why

The dashboard shows a lot of numbers (current conditions, 24 hourly points, 7 days), but users have to piece together what actually matters for their day themselves. A short, plain-language briefing generated by Azure OpenAI from the same Open-Meteo data gives an at-a-glance answer, and demonstrates a keyless, managed-identity AI integration for the capstone.

## What Changes

- Add a server-side Azure OpenAI client authenticated with Microsoft Entra ID (`DefaultAzureCredential` bearer tokens). Configuration comes from `AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_DEPLOYMENT`, and `AZURE_OPENAI_API_VERSION`. No API keys are used or accepted.
- Add a forecast summarizer that sends only a compact JSON view of the forecast (current conditions, next 24 hours, next 3 days, units) with a constrained system prompt: 2-3 plain sentences that call out rain timing, large temperature swings, and wind, use only numbers present in the data, keep the given units, and include no emojis or non-weather advice. It uses a low temperature and a cap of about 120 output tokens.
- Cache summaries per location + units + forecast-local hour so repeat views within the hour do not call the model again.
- Add an "AI summary" section above the current-conditions card. It streams in its own Suspense boundary with a one-line skeleton, so the rest of the dashboard never waits on the model.
- Fail soft: if the AI configuration is missing or any AI call fails, the section renders nothing, the error is logged server-side, and the rest of the dashboard renders normally.
- Document the new environment variables and the Azure role the runtime identity needs.

## Capabilities

### New Capabilities
- `ai-summary`: AI-generated plain-language weather briefing for the active dashboard location and units. Covers content constraints, input minimization, keyless authentication, per-hour caching, non-blocking display, and fail-soft behavior.

### Modified Capabilities
<!-- None. Existing weather-dashboard requirements are unchanged; the summary is an additive section whose placement, loading, and failure behavior are owned by ai-summary. -->

## Impact

- **New code**: `lib/ai/client.ts`, `lib/ai/summary.ts` (plus a cached wrapper), `components/AiSummary.tsx`, with tests for the summarizer and the component.
- **Modified code**: `app/page.tsx` renders the summary above `CurrentCard` inside the existing keyed forecast boundary.
- **Dependencies**: `openai` and `@azure/identity` are already declared in `package.json`. No new packages.
- **External systems**: a new runtime dependency on an Azure OpenAI deployment. Weather data still comes only from Open-Meteo; the model only rephrases it. The deployed App Service identity needs the `Cognitive Services OpenAI User` role on the Azure OpenAI resource. Provisioning that resource and role assignment is out of scope and documented only.
- **Config**: three new environment variables (local `.env.local` and App Service app settings). When they are absent the feature is silently disabled.
- **Cost/latency**: one small chat completion per location/units/hour, off the critical rendering path.
